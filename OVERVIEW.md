# What Red Set ProtoCell Does in One Run

## The Problem: Unknown AI Failure Modes

Most AI risk comes from **unknown failure modes**—the ways language models fail that nobody anticipated during development. Static test suites and manual red teaming only find known issues. Real-world adversaries adapt and evolve their attacks. Models are deployed faster than they can be thoroughly tested, and safety failures emerge in unexpected contexts that weren't covered by pre-deployment testing. The fundamental challenge is discovering these unknown vulnerabilities before they're exploited in production or discovered by users, rather than reacting after the fact.

## The Solution: Dual-Agent Evolutionary Red Teaming

Red Set ProtoCell discovers unknown failure modes through **adversarial evolution**. It uses a dual-agent architecture where the Sniper agent generates adversarial prompts using evolutionary algorithms and mutation strategies, while the Spotter agent independently evaluates target responses and scores failures without any ability to generate attacks. These prompts are sent to the target LLM via real API integrations, responses are analyzed using a three-layer scoring taxonomy (Linguistic Safety, Security Exploitability, Cognitive Stability), and successful attack patterns influence the next generation through fitness-guided selection. Unlike manual testing, this system operates autonomously 24/7, continuously adapting its attacks based on what works and discovering novel, emergent failure modes that human testers might miss.

## Why It's Trustworthy: Locked Policies and Reproducible Evidence

Red Set ProtoCell produces **defensible, auditable, and replayable evidence** of discovered failures. At the start of every run, it generates an immutable Attack Manifest that locks the policy version, mutation operators, fitness function, target definition, and random seed—creating a permanent record of the experiment's constraints. Every discovered failure is captured as a structured Failure Specimen containing the prompt genome, model response, evaluation scores, evolutionary lineage, and replay instructions. These artifacts are persisted to disk in a standardized directory structure (`runs/<manifest_id>/manifest.json` and `runs/<manifest_id>/specimens/*.json`), enabling independent verification, comparison across model versions, regression testing of defenses, and proof that discoveries weren't cherry-picked. The system enforces deterministic evolution via seeded RNG, meaning the same manifest and seed will produce the same results, making experiments fully reproducible.

## What It Is Not: Not a Safety Filter, Guardrail, or Autonomous Mitigation System

Red Set ProtoCell is an **offensive security testing platform**, not a defensive tool. It is not a safety filter that blocks harmful content, not a guardrail that protects model outputs, and not a compliance tool that certifies models as "safe." It discovers failures but does not fix them—remediation is the responsibility of model developers and deployers. It requires explicit authorization to test systems (analogous to penetration testing tools like Metasploit or fuzzers like AFL), and must only be run against models you own or are authorized to test. The system enforces strict scope boundaries, resource budgets, and deterministic replay to prevent abuse, but misuse constitutes a violation of operator responsibility. Think of it as offensive security instrumentation for AI systems: it provides reproducible evidence of vulnerabilities, not automated solutions.
